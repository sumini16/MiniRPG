# MiniRPG — Wave Arena Action Prototype

어두운 아레나에서 몰려오는 몬스터 웨이브를 버티고, 마지막에 나타나는 보스를 쓰러뜨리는 Unreal Engine 5.5 C++ 액션 프로토타입입니다.

완성된 게임보다 전투·AI·데이터 구조를 왜 그렇게 만들었는지 설명할 수 있는 수준까지 만드는 것을 목표로 했습니다.
같은 목표로 만든 Unity 프로젝트 [Pomomo_Prototype](https://github.com/sumini16/Pomomo_Prototype)이 퀘스트·인벤토리·세이브 같은 시스템 설계를 다뤘다면, 이 프로젝트는 전투·AI·엔진 이해에 집중했습니다.

| | |
|---|---|
| 환경 | Unreal Engine 5.5 · C++ · JetBrains Rider · Enhanced Input · Behavior Tree · UMG |

## 플레이 흐름

```
WAVE 1  미니언 무리 5마리        ─┐
WAVE 2  정예 몬스터(Buff) 8마리  ─┤  처치할 때마다 경험치 → 레벨업
BOSS    Rampage 등장 포효 → 전투  ─┘
   ↓ 보스 처치                    ↓ 플레이어 사망
 CLEAR                        YOU DIED  →  다시 시작
```

### 조작

| 키 | 동작 |
|---|---|
| WASD / 마우스 | 이동 / 시점 |
| 좌클릭 | 3단 콤보 공격 |
| Q | 회전베기 (범위 공격 · 넉백 · 히트스톱, 쿨타임 6초) |
| Shift | 대시 (쿨타임 3초) |
| Space | 점프 |

## 핵심 구현

### 1. 게임 흐름은 GameMode가, 스폰은 Spawner가
- `AMiniRPGGameMode`가 웨이브 배열(`TArray<FWaveInfo>`)을 순서대로 진행하고, 모든 웨이브가 끝나면 보스를 소환합니다.
- `AMonsterSpawner`는 "몇 마리, 몇 초 간격, 동시 몇 마리, 어떤 데이터로"만 받아서 스폰합니다. 언제 시작하고 멈출지는 모릅니다.
- 몬스터 사망은 `StatComponent.OnDeath → Spawner.OnMonsterKilled → GameMode`로 전달됩니다. 각 단계는 다음 단계를 알지 못합니다.

### 2. 몬스터 종류 = 데이터 파일 수 (`UMonsterData`)
- 체력·공격력·이동 속도·공격 범위·크기·메시·애니메이션 BP·공격/피격/사망/등장 몽타주·효과음을 하나의 `PrimaryDataAsset`에 묶었습니다.
- 몬스터 클래스는 하나(`AMonsterBase`)이고, 웨이브마다 다른 DataAsset을 지정하면 같은 오브젝트 풀에서 꺼낸 몬스터가 다른 종류로 바뀌어 나옵니다.
- 메시·애님 BP·몽타주는 같은 스켈레톤끼리만 동작하므로, 따로 바꾸다 깨지지 않도록 한 세트로 묶었습니다.

### 3. 오브젝트 풀링 — 측정으로 확인
| 방식 | 전투 중 몬스터 1마리 준비 시간 (평균, n=30) |
|---|---|
| 풀링 OFF (매번 SpawnActor) | 6.18 ms |
| 풀링 ON (미리 생성 후 활성화) | 0.10 ms (약 62배 빠름) |

스포너에 풀링 스위치를 두고, 스폰 직전부터 활성화 완료까지를 `FPlatformTime`으로 측정했습니다.
60fps의 한 프레임 예산은 16.7ms입니다. 풀링 없이 몬스터 한 마리를 만들면 그 약 37%를 쓰고, 같은 프레임에 3마리만 나와도 예산을 넘겨 끊김이 생깁니다. 비용의 대부분은 AI 컨트롤러·컴포넌트·위젯 생성과 BeginPlay 초기화입니다. 풀링은 생성 비용을 전투 중에서 레벨 로딩 시점으로 옮기는 기법이라, 몬스터가 한꺼번에 몰려나오는 웨이브 구조에서 프레임이 튀지 않게 합니다.
Unity 프로젝트 Pomomo에서는 적이 3마리뿐이라 차이가 측정되지 않아 풀링을 넣지 않았고, 이번에는 30마리 웨이브로 직접 비교했습니다.

- 몬스터를 미리 생성해 두고 비활성화·재사용합니다.
- 비활성 시 숨김·콜리전·Tick·이동뿐 아니라 Behavior Tree까지 `StopLogic()`으로 멈춰, 숨겨진 몬스터가 CPU를 쓰지 않게 했습니다.
- 재활성 시 `ApplyMonsterData()`로 수치·외형을 다시 적용하고, 사망 몽타주와 누적 속도를 초기화합니다.

### 4. AI — Perception + Behavior Tree + C++ 태스크
```
Selector
 ├ [TargetActor 있음 · aborts both] Sequence → Move To(Target) → Attack
 └ Sequence → Find Wander Location → Move To(WanderLocation) → Wait 2±1초
```
- 배회 → 발견 → 추격: 타겟이 없으면 C++ 태스크 `UBTTask_FindWanderLocation`이 NavMesh 위의 랜덤 지점을 골라 어슬렁거립니다. `AIPerception`(시야)이 플레이어를 감지하면 조건 데코레이터가 배회를 즉시 중단하고 추격으로 전환합니다.
- 무리 반응: 한 마리가 플레이어를 발견하거나 맞으면 `AlertNearby()`로 반경 안의 동료에게 알립니다. 알림을 받은 쪽은 다시 전파하지 않아 연쇄 호출을 막습니다.
- 늘어짐 방지: 일정 시간(기본 15초) 타겟이 없으면 플레이어를 추격합니다. 웨이브가 멈춘 것처럼 보이는 시간을 없애기 위한 장치로, 보스는 0초로 두어 등장 직후 추격합니다.
- 공격은 C++ 태스크 `UBTTask_Attack`이 사거리를 판단하고, 타겟이 죽었으면 Blackboard를 비워 시체를 공격하지 않습니다.

### 4-1. 보스 패턴 — 예고 후 범위 공격
- 일정 간격마다 플레이어 발밑에 붉은 경고 원을 표시하고, 1.2초 뒤 원 안의 대상에게 큰 피해를 줍니다. 플레이어는 대시로 피할 수 있습니다.
- 경고 원 위치는 플레이어 위치에서 아래로 라인 트레이스해 바닥 높이에 맞춥니다.
- 간격·경고 시간·반경·배율·몽타주·이펙트·카메라 셰이크를 모두 `UMonsterData`에서 설정합니다. 일반 몬스터는 패턴을 끈 같은 클래스입니다.
- 보스가 죽거나 비활성화되면 타이머와 경고 원을 함께 정리합니다.

### 5. 전투와 타격감
- 판정: `SphereTraceMulti` + `TSet`으로 한 액터의 여러 콜리전이 중복으로 맞는 것을 막았습니다. 몬스터끼리는 서로 피해를 주지 않습니다.
- 모션과 판정 분리: 공격 몽타주를 먼저 재생하고, 휘두르는 타이밍(`HitDelay`)에 타이머로 판정합니다. 플레이어는 3단 콤보로 순환합니다.
- 경직: 몬스터는 맞으면 피격 모션과 함께 예약된 공격 판정이 취소됩니다. 먼저 때리면 상대 공격을 끊을 수 있습니다. 보스는 피격 모션 없이 공격을 이어가도록 데이터에서 비워 두었습니다.
- 피드백 조합: 애니메이션 외에 히트스톱(전역 시간 0.05배 · 0.08초), 넉백, 카메라 셰이크, 이펙트 크기를 스킬 데이터(`USkillData`)로 조절합니다.

### 6. 델리게이트 기반 UI
- 체력·경험치·웨이브 진행·보스 등장·안내 문구를 모두 델리게이트로 받아 갱신합니다.
- 하나의 C++ 위젯 클래스(`UHealthWidget`)를 플레이어 HUD와 몬스터 머리 위 체력바가 같이 쓰므로, 공통 요소만 `BindWidget`, 일부만 쓰는 요소는 `BindWidgetOptional`로 나눴습니다.
- 스킬 쿨타임은 위젯이 남은 비율을 읽어 아이콘 위에 덮습니다.

## 설계 판단

| 판단 | 이유 |
|---|---|
| 몬스터 수치·외형을 DataAsset으로 분리 | 종류가 늘어도 코드·BP 수정이 없고, 풀 하나로 여러 종류를 표현 |
| 사망 처리를 `OnDeath` 델리게이트로 | StatComponent는 알림만, 반응은 각자 (몬스터는 디스폰, 플레이어는 게임오버) |
| 게임오버·클리어 UI를 Controller가 담당 | 체력 HUD도 Controller가 관리 → UI 책임을 한 곳에. Character는 입력·물리만 |
| StatComponent의 Tick 끄기 | 체력은 피격 시에만 변함 → 몬스터 수만큼 낭비 |
| 보스는 풀에 넣지 않음 | 한 번만 등장 → GameMode가 직접 스폰하고 사망을 구독 |
| 판정을 타이머로 지연 | 외부 에셋 몽타주를 수정하지 않기 위해. 한계: 몽타주 재생 속도가 바뀌면 어긋남 → AnimNotify가 더 정확 |
| 카메라가 몬스터를 무시 | 몬스터가 카메라와 캐릭터 사이를 지날 때 화면이 급격히 당겨지는 문제 방지 |

## 트러블슈팅 (주요 사례)

전체 기록 21건 이상 중 엔진 동작을 이해해야 풀 수 있었던 사례입니다.

캐시된 컴포넌트 포인터가 CDO를 가리킴
트레이스는 몬스터를 잡는데 데미지가 들어가지 않았습니다. Owner 이름과 포인터 주소를 로그로 비교하자 Owner가 `BPGC_ARCH_FOR_CDO_...` — 월드 인스턴스가 아니라 클래스 기본 객체의 컴포넌트였습니다. BP 생성 후 C++ 컴포넌트 구성을 여러 번 바꾸며 재인스턴싱이 어긋난 것으로, `FindComponentByClass`로 실제 부착된 컴포넌트를 조회하도록 바꿨습니다.

Dynamic 델리게이트를 두 줄로 써서 에러 14개
C++ 문법상 문제가 없는데 관련 없어 보이는 에러가 쏟아졌습니다. UHT는 헤더를 텍스트로 파싱하기 때문에 매크로 줄바꿈을 인식하지 못했고, 생성 코드가 깨지며 같은 파일의 다른 델리게이트까지 연쇄로 실패했습니다.

풀에서 재사용된 몬스터가 맞지 않음
사망 시 `SetCollisionEnabled`(컴포넌트 단위)로 끈 캡슐을, 재활성 때 `SetActorEnableCollision`(액터 단위)으로만 켜고 있었습니다. 별개의 스위치라 같은 단위로 짝을 맞췄습니다.

Paragon 보스가 서 있는 자세로 미끄러짐
속도를 낮춰도 같아서 애님 BP 쪽으로 범위를 좁혔습니다. 애님 BP는 가속도로 이동을 판단하는데, AI 경로 이동(MoveTo)은 기본적으로 가속 없이 속도를 직접 넣습니다. 애님 BP를 고치는 대신 `bUseAccelerationForPaths`를 켜서 해결했습니다. 8월에 같은 증상을 애님 BP 복제로 우회했던 문제의 근본 원인을 두 번째에 찾은 사례입니다.

핫 리로드 중 Blueprint 재인스턴싱 크래시
에디터를 켠 채 클래스 구조를 바꿔 빌드하자 크래시와 함께 BP에 붙인 컴포넌트가 사라졌습니다. 빌드 로그의 `UnrealEditor-MiniRPG-0005.dll`처럼 DLL 이름에 번호가 붙는 것이 핫 리로드의 신호임을 확인하고, "저장 → 에디터 종료 → 빌드"를 고정 절차로 만들었습니다.

OnPossess가 BeginPlay보다 먼저 호출됨
HP UI가 갱신되지 않았습니다. 위젯이 생성되기 전에 바인딩을 시도하고 있었고, 바인딩을 분리해 두 시점 모두에서 호출하되 중복 구독은 `IsBoundToObject`로 막았습니다.

## AI 활용 방식

이 프로젝트는 AI(Claude)와 협업해 만들었습니다. 역할은 이렇게 나눴습니다.

| AI | 직접 |
|---|---|
| 설계 선택지 제시, 코드 초안, 원인 후보 정리 | 기획·우선순위 결정, 빌드·테스트, 에디터 작업, 최종 판단 |

AI가 제시한 코드가 틀린 경우도 있었고, 대부분 빌드와 플레이 테스트로 잡았습니다.
- UE 5.4에서 구조체로 옮겨진 `bUseAccelerationForPaths`를 옛 이름으로 제시 → 컴파일 에러로 발견, `NavMovementProperties`로 수정
- 정상 동작하던 `UNavigationSystemV1::GetCurrent` 호출을 잘못 바꿈 → 빌드 에러로 발견, 원복
- 모듈 루트 폴더 헤더의 include 경로 누락 → `Build.cs`에 경로 추가

"더 강해 보이는 몬스터로", "맞는 반응이 없다", "소리가 없어 재미가 없다"처럼 플레이해 보고 느낀 문제를 먼저 정의하고, AI와 해결 방법을 비교한 뒤 구현했습니다. 발생한 문제와 판단은 모두 별도 문서에 기록했습니다.
